01 · Business Problem

The Hidden Cost of Invisible Debt

Technical debt is invisible to business leaders. Executives see symptoms — missed deadlines, escalating estimates, failing releases — while engineers see structural root causes. Without shared visibility, decisions stall and costs compound.

~$12,000

Lost per decision cycle spent debating "build now vs. refactor first" without shared data

$200,000+

Typical cost of a system failure caused by deferred technical debt in production

$40K–$80K

Monthly drag from ongoing inefficiencies — slower feature velocity, rework, and engineer frustration

The Gap

Product requests optimistic timelines. Engineering identifies longer rebuild needs. No shared framework exists to reconcile both views objectively.

03 · Design Decisions

Why These Choices?

Two foundational decisions shaped the architecture and determined success.

Decision 1 · Architecture

✓ Multi-Agent Pipeline chosen

A single-agent monolith exceeded token limits for repositories over 100 files, produced inconsistent outputs, and cost $1.50/analysis. The multi-agent pipeline reserves Claude only for reasoning stages, cutting cost to $0.35 (77% savings) while improving reliability — deterministic stages eliminate hallucination risk entirely.

Decision 2 · Output Format

✓ Strict JSON Schema chosen

Free-form text produced ranges ("expensive") rather than numbers, making ROI calculations impossible. A strict JSON schema with validation rejects invalid values, enables programmatic chart rendering in the React UI, and raised valid output rate from 45% to 98% — a 118% improvement in structural consistency.

05 · Iteration History

From Proof-of-Concept to Production

v1.0 — Proof of Concept

Monolithic Approach — Failed

Single Claude call for the entire workflow. Worked only for repos under 10 files. Token exhaustion killed real-world use. Output was unstructured text — not parseable for ROI calculations.

v1.5 — Initial Structure

3-Agent Split — Improved

Split into scan → analyse → recommend stages with a basic JSON schema. Reliability improved but cost estimates hallucinated wildly — ranging from $200K to $2M for identical debt patterns.

v2.0 — Benchmark Validation

CostModel + JiraFetcher Added

Added Stage 4 CostModelAgent to validate against DORA metrics and Stage 2 JiraFetcherAgent to cross-reference features. Pattern accuracy jumped to 87%, cost variance stabilised to ±28%.

v2.5 — Production Ready

Fully Operational

Added result caching, interactive React demo, comprehensive error handling, and sub-60s analysis times. Output quality became consistently production-grade and suitable for real-world deployment.

09 · Ethical Considerations

Responsible AI by Design

Risk: Over-Reliance

AI Can't Replace Judgment

Outputs are clearly labelled as recommendations, not mandates. Confidence levels are tied to data quality. Manual overrides are explicitly supported.

Risk: False Precision

Showing Uncertainty

All cost estimates are presented as ranges with visible confidence intervals. Benchmark assumptions are explained, not hidden. Engineers familiar with the codebase must validate.

Risk: Job Security

Decision Support, Not Evaluation

Positioned as a starting point for discussion, not performance measurement. Engineering leadership is involved in rollout. Estimates are not used for headcount decisions.

Risk: Bias

Context-Aware Calibration

Default cost models assume US senior engineers — teams are prompted to adjust for geography, skill level, and company size before acting on estimates.
